## Qué significa, en palabras simples

Hasta ahora el proyecto sabe **calcular** planes de semáforo (DEV13, DEV14, DEV15). DEV16 es la primera vez que aprende de ejemplos: se le muestran muchos casos (demanda de entrada → el mejor plan encontrado con SUMO) para que, ante un caso nuevo, proponga un plan sin tener que buscarlo otra vez.

Se entrenan dos predictores:
- **La mediana:** para cada salida (ciclo y verdes), el valor del medio de lo visto en entrenamiento. Es el predictor sencillo que la tesis compara contra el modelo.
- **XGBoost:** un método de árboles de decisión, el candidato a superar a la mediana. Se decide con datos de desarrollo, no por preferencia.

## Decisiones que propone el equipo (F0)

- **D1. Orden:** primero la mediana (no necesita librerías ni DEC09), después XGBoost.
- **D2. Partición:** se usa la partición de DEV12 por grupos de escenarios. El conjunto de prueba se reserva; el modelo se elige con validación. Nada del conjunto de prueba entra a la selección.
- **D3. Mismas entradas y salidas para ambos:** el mismo vector de entradas ordenado (demanda por movimiento y proporciones por clase). Ambos pasan las mismas reglas de factibilidad (ADR05).
- **D4. Selección:** el orden de decisión se fija antes de entrenar: primero factibilidad, después cobertura, después error en validación, al final costo. No se elige por preferencia de herramienta.
- **D5. Semillas y versiones:** semilla fija; versión exacta de XGBoost fijada tras una prueba de instalación (ADR08). No se usa «la última versión».
- **D6. Sin reentrenar con el conjunto de prueba:** el reentrenamiento con entrenamiento más validación solo se permite después de fijar la configuración, y queda registrado.
